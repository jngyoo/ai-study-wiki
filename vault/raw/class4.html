The Limitation of Classic ML

For images and speech, deciding which input features to measure can be much of the work.

  • In a spreadsheet, we can choose columns such as price, usage, and days since purchase.
  • In an image, we start with pixel brightness. Which combinations distinguish one shape from another?
  • A neural network can learn useful combinations of those inputs during training.

We still choose the data, architecture, and training objective. The network learns the intermediate features.

Deep Learning Learns Multiple Layers of Representation

pixel values → simple patterns → combinations → prediction
  • A representation is a way of describing the input with numbers.
  • Each layer transforms the previous layer’s numbers into another representation.
  • Training adjusts those transformations to make the final prediction more useful.

Deep means multiple learned layers. We will first see how a small network works, then apply the same ideas to language.

A Neural Network Is Still a Function

A neural network turns input numbers into output numbers using adjustable weights and biases.

  • Architecture: which neurons connect to which other neurons.
  • Parameters: the weights and biases on those calculations.
  • Training: change the parameters to reduce loss on examples.
  • Inference: use the learned parameters to predict for a new input.

Keep asking: what goes in, what comes out, and which numbers change during training?

Neural Networks

The Artificial Neuron

An artificial neuron is a small calculation, loosely inspired by biological neurons.

  1. Receive inputs: numbers from the data or an earlier layer.
  2. Multiply each input by its weight, then add the results.
  3. Add a bias: a learned offset.
  4. Apply an activation function and pass the output onward.

One neuron makes one feature. Connecting many neurons lets the model combine features.

Weights scale the inputs. Bias shifts the sum. Activation turns it into a score.

One neuron, one decision: take inputs, multiply by weights, output a score. Score > 0.5 → Yes. Score < 0.5 → No. That’s classification. One neuron isn’t smart: but millions together can recognize faces, translate languages, and write code.

The Neuron as a Formula

output = activation(weight₁ × input₁ + weight₂ × input₂ + bias)
  • A weight controls how an input changes this neuron’s calculation. It can be positive, negative, or near zero.
  • The bias shifts the calculation, like the intercept in a regression.
  • The activation bends the response. The next layer receives this result.

How a Neural Network Learns

Imagine a row of adjustable dials. Together, their settings determine the prediction.

  1. Predict: pass an example through the network with the current settings.
  2. Measure loss: compare the prediction with its training target.
  3. Backpropagate: calculate how a small change to each setting would change loss.
  4. Update: use those gradients to adjust the weights and biases.
  5. Repeat: use many examples, then check held-out examples.

Backpropagation measures sensitivity. The optimizer uses that information to move the dials.

How Does an Earlier Weight Affect the Loss?

Follow the orange path: an early weight changes a hidden value, which changes the prediction, which changes the loss.

1. Start at the lossCompare the prediction with the target: stripe.

2. Trace the influenceBackpropagation works backward through the calculations, including the hidden layers.

3. Get a gradientFor each parameter: if it increases a little, does loss rise or fall?

Hidden layers need no separate labels. The final loss gives us gradients for their weights and biases.

Use this after the earlier interactive training loop, not as another click-through of the same steps. The new question is how an early connection can be trained when we only label the final answer.

Start with the literal thin black line on white. The toy input samples three positions: above the line, on the line, and below the line. Their brightness values are 1, 0, 1. The sample markers show which three locations we read; the network still receives just three numbers. Follow the blue arrows from those locations to the input neurons.

Then point to Target: stripe and Loss. Prediction alone cannot tell us whether we got the intended answer. For this classifier, cross-entropy loss is minus the natural log of the target probability. More probability on stripe means lower loss, even before stripe becomes the highest-probability class.

Trace the orange path forward with your finger: changing this input-to-hidden weight changes a hidden activation, which changes the output and loss. Then trace backward: backpropagation combines local sensitivities along the calculation paths, using the chain rule, to compute a gradient for every weight and bias. The orange path isolates one route to follow; the real calculation combines all routes through which a parameter affects loss. The output probabilities are coupled through softmax. No separate human-provided target is needed for each hidden neuron.

A positive gradient means a small parameter increase raises this loss; gradient descent therefore decreases it. A negative gradient means a small increase lowers this loss, so gradient descent increases it. A near-zero gradient means little immediate effect for a tiny change. This is local sensitivity, not a measure of blame or importance. Weights remain fixed while we calculate these gradients. The optimizer updates them next.

Ask: if the label is only at the output, can a first-layer weight still learn? Yes, because its effect on the final loss can be traced through the intermediate calculations.

Batches Make Training Practical

A mini-batch is a small group of training examples used for one update. Here, the batch is four pictures.

1. Predict and comparePredict for each picture and measure its loss against its label.

2. Combine the feedbackBackpropagation gives gradients for each example. Average those gradients.

3. Update onceApply one update to the shared weights and biases. Then take the next batch.

Examples can pull a parameter in opposite directions. The batch update follows their average, not the last example alone.

Use the same stripe-versus-solid task as the earlier network slides. Point to each literal picture and its label: these are four examples in one illustrative mini-batch, not four inputs to a single prediction. Each picture is represented by sampled pixel values, as before. The two stripe cards represent separate examples of the same class; the two solid cards show black and white.

All four examples use the same parameter values before this update. The network makes a prediction for each example; its label gives a loss. Backpropagation computes the gradients, and the optimizer uses their average to update the shared weights and biases once. Equivalently, differentiate the mean loss. The orange paths summarize this backward calculation; losses are not themselves gradients. Averaging happens separately for every trainable parameter.

Four examples means one update here, not four updates. Ask: if we have twelve pictures and a batch size of four, how many updates make one full pass? Three. Use the answer to introduce the next slide on epochs. Smaller batches let us train without holding the entire dataset’s intermediate calculations in memory at once, and can make efficient use of parallel hardware.

Why GPUs Help Train Networks

Training repeats many similar calculations across neurons and examples.

  • A layer can be calculated as a matrix multiplication, followed by bias and activation.
  • Many of those calculations can run at the same time.
  • GPUs provide hardware for doing large groups of numerical operations in parallel.

The small network we just trained uses the same basic learning loop. A larger network needs more memory, computation, and data.

The illustration shows simplified data-parallel training: GPUs process different slices of a batch using copies of the same weights. Each GPU computes a forward pass and gradients; those gradients are combined before the optimizer updates the shared parameters. The zoom shows one row of inputs multiplied by the weight matrix, before bias and activation. Every entry in the weight matrix is a learned parameter; biases are also parameters but omitted from the drawing. Matrix multiplication computes layer scores; the optimizer performs the parameter update. Teaching Machines to Read

Why Language?

The Problem: Words Aren’t Numbers

How do you feed words into a neural network that only understands numbers?

An embedding is a learned vector (a list of numbers) that represents a word or token. Training adjusts these numbers to help the model make predictions.

Warning

Both words use the same dimensions, in the same order. These values and labels are simplified examples; real dimensions are learned and blend many concepts. Words used in similar contexts tend to have similar embeddings.

Word2Vec (2013) learned that words in similar contexts get similar vectors.

Context Determines Meaning

One vector per word has a ceiling: “bank” in a finance memo and “bank” in a river report should not mean the same thing.

Word2Vec gives both banks the same point in space: a learned representation based on the contexts in its training corpus. Modern models instead create contextual representations: the vector for “bank” is adjusted, on the fly, by the words around it. The mechanism that does that adjusting is attention: coming right up.

How Words Become Tokens

A tokenizer breaks text into pieces called tokens. BPE (byte-pair encoding) learns which pieces to combine.

Illustrative split, IDs, and vectors. Each model uses its own fixed tokenizer.

One word, three tokens: each takes context space and can contribute to API cost.

Follow the illustration from top to bottom. The top row spells unbelievable. The example compresses multiple pair merges into each pictured stage. The middle row has un, bel, iev, able. The final row combines bel and iev into believ, giving three tokens: un, believ, able. Each ID selects a row in the model’s learned embedding table. A token ID is a lookup index, not a measure of meaning. The network computes with the selected vectors.

BPE vocabulary construction starts from small units, such as bytes or characters. Count adjacent pairs across the training text, merge a frequent pair, update the counts, and repeat until the desired vocabulary size is reached. The tokenizer learns these merge rules ahead of use. For a new prompt, it applies the saved rules rather than learning new ones. The drawing summarizes vocabulary construction and encoding, which happen at different times.

The split and all numbers in the illustration are invented for teaching. BPE merges reflect frequency, so pieces need not be meaningful word parts. Tokens may also include whole words, punctuation, spaces, or bytes. Byte-based tokenizers can represent unfamiliar text using smaller pieces. Real embedding vectors usually contain many more numbers, indicated here by the ellipses. Different tokenizers may produce different splits and token counts for the same text. Check the tokenizer for the model you use.

Talking in Tokens

Sequences & Attention

The Problem with Order

“Dog bites man” and “man bites dog” use the same words but mean different things.

  • A representation that only counts words loses their order.
  • A network can use order if the input and architecture preserve it.
  • Sequence models are designed to work with positions and context.

The design question is: how should information at one position influence another?

RNNs: Adding Memory

Recurrent Neural Networks (RNNs) process sequences one step at a time, passing a “memory” forward to the next step: a running state that summarizes everything read so far.

The fading arrows illustrate a possible difficulty with long-range information, not a fixed five-word memory limit. Each recurrent step depends on the previous state.

The Bottleneck Problem

A recurrent network carries a fixed-size state from one position to the next.

  • That state must retain useful details from earlier positions.
  • Long-range relationships can be difficult to learn and preserve.
  • The dependence on the previous state limits parallel processing across positions.

Attention offers a more direct route between positions. It does not need to pass every detail through a single running state.

The hidden state is a fixed-length vector of numbers, updated at each position. The four colored slots stand for vector dimensions, not four words or four permanent facts; their values change at every step. h0 is the initial state, often initialized to zeros. Each RNN box reuses the same learned network with a new input token and the previous state. Input words stand in for tokens; their embeddings enter the computation. The ellipsis represents additional token positions. Long-range information can be difficult to preserve, but there is no fixed token count at which an RNN must forget. The illustration emphasizes constant state size, not a measured rate of forgetting.

Original illustration generated with the built-in image-generation tool. Prompt: diagrams/c4-rnn-bottleneck-prompt.md.

“Attention Is All You Need” (2017)

In 2017, Google researchers published arguably the most important AI paper of the decade. The solution to RNNs forgetting and being slow? Don’t process words one at a time at all.

They introduced the Transformer: built entirely on a mechanism called attention, with no recurrence. Every major AI model today: GPT, Claude, Gemini, LLaMA: is a transformer.

Attention Changes the Question

Attention combines information from the token positions available to the current position.

  • A recurrent network passes a state forward through the sequence.
  • Attention can connect directly to earlier positions within the context window.
  • In a GPT-style model, a causal mask blocks future tokens.

Training can process many positions in parallel while respecting that mask. Generating new text still proceeds one token at a time.

Attention: Which Tokens Can It Use?

Select a position. Which tokens is it allowed to use to predict the next token?

In a GPT-style model, a position can attend to itself and earlier positions. Future positions are masked out. Allowed does not mean equally useful.

Causal masking and attention reference: Vaswani et al., Attention Is All You Need, https://arxiv.org/abs/1706.03762. The interactive mask represents the decoder self-attention restriction.

Attention Updates Meaning

After attention, the embedding for “mole” has been pulled toward the right meaning by its context:

“American shrew” pulls “mole” toward the animal direction. “Carbon dioxide” pulls it toward the chemistry direction. Same starting point, different ending: that’s what attention does.

Image: 3Blue1Brown

How Attention Combines Context

  1. Find useful context: compare the current token with the tokens it can use.

  2. Set the mix: give more relevant tokens a larger share.

  3. Update meaning: combine their information with the current representation.

Queries and keys produce compatibility scores. Softmax converts the allowed scores into mixing weights that sum to one. Those weights determine how much each value vector contributes. The model transforms the mixture and adds the result to the current representation.

The image illustrates the flow of information. Its chemistry example uses context on both sides of mole. A causal GPT model can use only the token itself and earlier tokens. Attention weights describe information mixing, not the truth of a statement.

Source: https://www.3blue1brown.com/lessons/attention and Vaswani et al., Attention Is All You Need, https://arxiv.org/abs/1706.03762.

Attention Cost Matters

The price of “every word looks at every other word”: the work grows with the square of the length.

  • 1,000 tokens → 1M comparisons. 100,000 tokens → 10 billion. Doubling your document quadruples the compute
  • This is the engineering and economic constraint behind context windows: the caps on how much text a model can consider at once
  • It’s why long-context models cost more per request, why providers charge per token, and why “just paste the whole database into the prompt” is not an architecture

Note

When we discuss context windows, token economics, and retrieval in Class 5, this quadratic is the physics underneath every pricing table you’ll see.

How a Transformer Processes Text

Follow the numbered arrows across the top row, then back along the bottom row.

  1. Text in and tokenize: “The cat sat on the” becomes [The] [cat] [sat] [on] [the]. This is a simplified tokenization example; real tokens can be words, word pieces, or punctuation.
  2. Embed and add position information: each token becomes a learned vector of numbers. The model also receives information about token order. These initial vectors are refined using context.
  3. Transformer blocks: causal attention combines information from the current and earlier positions, blocking future tokens. A feed-forward neural network then refines each position’s representation. Both operations repeat across layers, with residual connections and normalization omitted from this overview for clarity.
  4. Predict: the final position’s representation is mapped to vocabulary scores. Softmax turns these scores into a probability distribution over possible next tokens. The displayed 60%, 25%, 10%, and 5% are illustrative; “other” groups the rest of the vocabulary.
  5. Sample: in this simplified sampling example, draw one of 100 equally likely integers, from 00 through 99. Values 00–59 select mat (60 numbers); values 60–84 select rug (25 numbers); values 85–94 select floor (10 numbers); values 95–99 represent other tokens (5 numbers). A draw of 73 therefore selects rug even though mat is most likely. Higher probability means more winning numbers and a greater chance of selection. Real samplers use the full vocabulary distribution, whose probabilities need not be whole percentages. Greedy decoding instead selects the highest-probability token; randomness is a decoding choice, not required in every generation mode.
  6. Append and repeat: the text is now “The cat sat on the rug”. Use the longer context to predict the following token, repeating until a stopping condition is reached. Implementations can cache earlier computations rather than recomputing everything.

Positional Information Preserves Order

The same word needs a signal for where it appears, as well as what it means.

  • RNNs tracked order one step at a time. Attention needs position information supplied explicitly.
  • Shown here: add a position vector to each embedding before attention mixes the context.

Both sentences contain exactly the same twelve words, including four copies of “the”, but reverse who thanks whom and change which event comes first. The word manager appears at position 5 in A and position 9 in B. Its initial word embedding stays the same; adding different position vectors produces different inputs to attention. This applies to every token, not just manager. Positions let the model weigh where as well as what, including earlier, later, and relative distance.

The numbered badges label token positions, not literal values added to embeddings. The four-number vectors are deliberately illustrative and their sums are exact. The image shows the original additive approach. Position can also be represented through the attention calculation itself, as with rotary position embeddings. Unrestricted self-attention without positional information is permutation-equivariant: reordering the inputs reorders the outputs, but does not encode which token came first. Attention weights need not be symmetric. Causal masking also provides an order-dependent restriction on which tokens can be used.

Residual Connections Keep Learning Stable

A detail that made 96-layer networks possible: each block adds its output to its input, rather than replacing it.

  • Layers refine an existing representation instead of repeatedly rebuilding it from scratch: edit the memo, don’t rewrite it
  • It also keeps backpropagation healthy: correction signals flow backward through the “shortcut” without fading across dozens of layers (the vanishing gradient problem that plagued early deep networks)
  • You’ve already seen this: the mole diagram: context is added to the original embedding. That plus sign is a residual connection

Scaling Laws: How Compute Improves Predictions

When model size and training data grow together, more training compute tends to reduce prediction loss.

Compute means the total calculations used during training, not just the number of GPUs or the elapsed time. A larger model takes more work per token, and processing more tokens takes more work overall. The server and clock make that accumulated work concrete.

Scaling laws are empirical patterns: within comparable training setups, loss often improves smoothly as model size, training data, and compute increase. Loss measures how well the model predicts held-out text; it is not a general intelligence score. This schematic uses ordinary qualitative axes and no measured values. It illustrates diminishing absolute improvements with additional compute, not an exact exponent or a guaranteed return on spending. Architecture, data quality, and the allocation of compute still matter. This slide concerns pretraining compute, not extra reasoning at inference time.

Pretraining Learns Broad Statistical Structure

The recipe behind every foundation model:

  • Take massive text corpora: a filtered slice of the internet, books, code
  • One task, repeated trillions of times: predict the missing or next token
  • No labels, no annotators: the text itself is the supervision. Every sentence is a tiny exam with the answer key attached
  • Result: surprisingly general capabilities: grammar, facts, style, reasoning patterns: from a task nobody would call intelligent

Note

Remember the labeling bottleneck from Class 3: “the biggest cost in ML is labeled data”? Pretraining is the industry-scale workaround: text supplies its own prediction targets if your task is “guess the next token.” Data still requires collection, filtering, and permission to use. That economic unlock, as much as any architecture, is why language became AI’s center of gravity.

Transfer Learning: Don’t Start From Scratch

Reuse a pretrained network as a starting point, then adapt it to another task.

  • A pretrained image network can be adapted to a smaller labeled image dataset.
  • A pretrained language model can be adapted using examples of a specialized task.
  • Fine-tuning changes parameters; providing context in a prompt does not.

Pretraining can be expensive at large scale. Our tiny classroom model is small enough to train from scratch.

Image: 3Blue1Brown

Fine-Tuning and Alignment Shape Behavior

A pretrained model is a text predictor, not an assistant. Two further stages shape behavior:

  • Fine-tuning: continue training on curated examples: your domain’s documents, or demonstrations of helpful question-answering
  • Alignment (RLHF: reinforcement learning from human feedback): humans rank the model’s answers; RL: the same reward-driven learning from Class 3’s Grid World and Pac-Man: nudges the model toward answers people prefer
  • These make a base model more helpful, safe, or specialized: but they do not make it omniscient. Tuning shapes how it answers, not what is true

GPT: Predict the Next Word, at Scale

GPT (Generative Pre-trained Transformer) has one training objective: predict the next token.

Given “The cat sat on the,” predict “mat.” That’s it: billions of times, on billions of documents.

From this simple objective, the model learns grammar, facts, reasoning, and coding: all as a side effect of getting better at prediction.

Note

GPT-1 (2018) had 117 million parameters. GPT-5 (2025) has an estimated 5 trillion. Same idea, 40,000x bigger: and the results went from “interesting toy” to “writes better than most humans.”

Beyond Text: The Same Machine, More Senses

Multimodal means working with more than one kind of data. Different inputs become vectors: lists of numbers that attention can combine.

Why it matters: Ask a question about a screenshot, discuss a recording, or describe an image to generate. Context limits, hallucinations, and processing costs still matter.

Read the picture from left to right. Text is split into tokens, images can be split into patches, audio into short frames, and video into image patches across time. Modality-specific encoders turn these pieces into numerical representations that the model can combine with attention. These are examples of common approaches, not one required architecture.

Training on related data across modalities teaches useful connections: an image of a dog, the words “a dog,” and a barking sound can refer to the same thing. This does not mean every model uses one identical embedding space or supports every input and output shown. The diagram shows possible inputs; they do not all have to be supplied for each question.

For the example, the question and image can be enough to answer “The dog is running.” A model that supports speech generation can also speak the response. Image generation requires a model with that output capability.

The transformer attention idea extends beyond language, but input encoders and output mechanisms can differ. Multimodal inputs still consume context and processing resources. Resolution, audio duration, video length, and the model’s encoding scheme affect cost. More senses do not make an answer automatically correct.
